# 핏 분석 앱 계획 — 2026-10-12 (사용자 결정)

체형 테스트 웹페이지(이 저장소)의 다음 단계. **필링데이가 자리 잡은 뒤** 시작한다.

## 결정 (2026-10-12 대화)
- 서버가 쇼핑몰을 미리 수집(크롤링)해 치수표 DB 를 만드는 방식은 **하지 않는다.** 약관 위반·데이터베이스제작자권 침해 위험, 경고장 한 장에 핵심 기능이 멈추는 구조.
- 링크를 넣으면 서버가 그 페이지를 가져오는 방식도 **하지 않는다.** 같은 문제.
- **최종: 사용자가 치수표를 찍으면, 저장된 내 치수·핏 선호와 대조해 사이즈별로 어떻게 맞는지 분석만 해 준다.** 사진은 사용자가 자기 폰에서 보는 화면을 찍는 것이라 자동 접근이 아니다.
- 사용자들의 치수표를 모아 공유 DB 를 만드는 것(모델명만 넣으면 바로 결과)은 **보류** — 출시 전 변호사 확인 뒤 결정. 그전까지는 각자 찍은 것만 쓴다.
- 브랜드가 치수 데이터를 직접 주는 제휴는 언제든 환영(법적 문제 없음).

## 첫 버전 기능
1. **내 치수 기록**(기기 저장, 동의 후): 어깨너비, 가슴·허리·엉덩이둘레, 팔뚝둘레(위팔 가장 굵은 곳), 팔길이, 허벅지둘레, 밑위·다리길이, 목둘레. 키·몸무게 선택.
2. **핏 선호**: 부위별 핏·보통·넉넉 (예: 팔뚝 넉넉, 허리 핏, 목 라운드). 기본 여유분은 의류 패턴 통상값에서 시작.
3. **내 옷장 보정**(선택): 잘 맞는 옷 한두 벌의 단면을 넣으면 부위별 "내 기준 여유분" 을 학습 → 정확도 상승.
4. **치수표 사진 분석**: 사진 → Gemini 비전(서버) → 사이즈별 가슴단면·어깨너비·소매통·허벅지단면 등 표 → 단면×2 − 내 둘레 = 여유분 → 핏 선호와 비교 → 사이즈별 판정 + 추천 사이즈 + "둘 다 만족하는 사이즈 없음" 안내. 소재(니트·스판) 표기를 읽어 여유분 보정.
5. **체형 유형**: 이 웹페이지의 판정(FFIT + 한국 여성 기준)을 앱에도 넣는다.
6. 결과 저장·공유는 치수 없이 판정만. 면책: 브랜드별 실측 오차, 치수표 없는 상품은 "판단 불가".

## 하지 않는 것
크롤링, 링크 자동 수집, 특정 상품 추천·제휴 링크(1차 버전), 서버 치수 저장(사진만 서버로, 결과는 기기로).

## 기술
필링데이 구조 복사(Flutter, Firebase, Functions asia-northeast3, Gemini 서버 호출, 자동화 사슬). 사진 인식 코드는 필링데이의 영양제 라벨 인식과 같은 모듈.
